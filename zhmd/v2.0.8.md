# 版本 2.0.8 — IP-Adapter ConvRot INT8 支持与运行时 UNet INT8 量化

本次发布新增了对 **ConvRot INT8 (HSWQ)** IP-Adapter 包的运行时支持，并使 UI Low Bits `int8` 选项在普通（非量化）checkpoint 上真正产生 INT8 存储。彻底解决了此前阻断 ConvRot INT8 IP-Adapter 包载入的 `RuntimeError: Error(s) in loading state_dict for Resampler` 中止问题，并通过 512x512 实机生成完成端到端验证（与 FP16 存储路径的像素 cosine 为 1.000000，无黑图、无 NaN 输出）。

---

## 1. 概述

| 项目 | 详情 |
|---|---|
| **影响范围** | 使用 ConvRot INT8 (HSWQ) 量化的 IP-Adapter（SD 1.5 Plus）检查点，以及在 UI Low Bits `int8` / `int8 (fp16 LoRA)` 选项下载入的任意普通（FP16/FP32）UNet checkpoint。 |
| **故障表象** | 1. **IP-Adapter 载入中止**：ConvRot INT8 IP-Adapter 包因 54 个 Unexpected `comfy_quant` / `weight_scale` 键而无法载入，抛出 `RuntimeError: Error(s) in loading state_dict for Resampler`，IP-Adapter 条件注入从未执行。<br>2. **静默保留 FP16**：在普通 checkpoint 上选择 `int8` 时，所有权重仍以 FP16 留存，仅在日志中记录 `ERROR: zero QuantizedTensor weights after load`。<br>3. **去量化探针浪费**：`ControlNetPatcher.try_build_from_state_dict` 在每次载入时对 IP-Adapter 包的副本执行一次无意义的去量化（每次 0.19 秒）。 |
| **技术根本原因** | `IPAdapter.__init__` 将原始 pack state dict（含 INT8 sidecar 键）直接交由 `Resampler.load_state_dict`，而该路径没有任何 INT8 处理。此外，`load_unet_int8_branch` 假设 checkpoint 已携带量化元数据，从未对普通权重进行量化。 |
| **核心架构解决方案** | 1. **ConvRot INT8 IP-Adapter 运行时**：新增 `extensions-builtin/sd_forge_ipadapter/lib_ipadapter/convrot_int8.py`，图像投影层与 IP-Attention 层保留 INT8 权重并通过 `comfy_kitchen.int8_linear(convrot=True)` 执行（图像投影 22 层 + IP-Attention 32 层）。<br>2. **Sidecar 感知载入**：`IPAdapter.__init__` 与 `To_KV.__init__` 检测 INT8 sidecar 并消费之，FP16 余量（norm、bias、latents）正常载入。Float 包走原路径不变（已验证：0 个 ConvRot INT8 模块）。<br>3. **运行时 UNet 量化**：`load_unet_int8_branch` 在载入过程中将普通 checkpoint 的权重即时量化为 tensorwise INT8（已验证运行：转换 282 个 Conv 层、跳过 0 层）。<br>4. **保护层保持 FP16**：已携带量化元数据的 checkpoint（含受保护的 FP16 层）绝不被重新量化。 |
| **性能实测提升** | IP-Adapter ConvRot INT8 包的 INT8 权重仅 46.78 MB（相对 FP16 源 158 MB）。UNet INT8 存储将权重字节数减半（已验证 mock：176,128 → 88,064）。512x512 生成：像素 cosine 1.000000（相对 FP16 存储路径），mean/std 103.9/62.4，近黑像素比 0.0000。 |

## 2. 技术背景与根本原因深度剖析

### 2.1 IP-Adapter 载入中止
在加载 IP-Adapter ControlNet 模型时，`extensions-builtin/sd_forge_ipadapter/scripts/forge_ipadapter.py` 中的 `IPAdapterPatcher.try_build_from_state_dict` 构建 `IPAdapter` 实例。`extensions-builtin/sd_forge_ipadapter/lib_ipadapter/IPAdapterPlus.py` 的 `IPAdapter.__init__` 调用：
```python
self.image_proj_model.load_state_dict(ipadapter_model["image_proj"])
```
对于 ConvRot INT8 包，state dict 包含 `comfy_quant` / `weight_scale` sidecar。`Resampler.load_state_dict` 将其作为 Unexpected keys 拒绝并抛出 `RuntimeError: Error(s) in loading state_dict for Resampler`，在任何 sample 运行前即中止。

### 2.2 静默保留 FP16
当在普通 checkpoint 上选择 UI Low Bits `int8` 时，`modules_forge/hswq_int8.py` 的 `load_unet_int8_branch` 使用 INT8 能力算子构建 UNet，但从未量化已载入的（FP16）权重，因为该分支假设 checkpoint 已携带 `comfy_quant` 元数据。结果是 `quantized_tensor_weights=0` 与日志中的 `ERROR: zero QuantizedTensor weights after load`，模型静默保持 FP16。

### 2.3 去量化探针浪费
`modules_forge/supported_controlnet.py` 的 `ControlNetPatcher.try_build_from_state_dict` 在 marker 检查前对 state dict 的副本执行去量化。由于 `modules_forge/shared.py` 的 `try_load_supported_control_model` 为每个 patcher 传递独立副本，IP-Adapter 包的 sidecar 在每次载入时都被去量化并丢弃（每次 0.19 秒）。

---

## 3. 核心修复方案与完整代码剖析

### 3.1 ConvRot INT8 IP-Adapter 运行时（`extensions-builtin/sd_forge_ipadapter/lib_ipadapter/convrot_int8.py`）
新增模块提供：
- `ConvRotInt8Linear`：保留 `int8_weight`（int8）与 `weight_scale`（float32）缓冲区；`forward` 调用 `comfy_kitchen.int8_linear(..., convrot=True, convrot_groupsize=...)`。`_apply` 覆写在 `.to(dtype=...)` 后将 scale 强制恢复为 float32。
- `split_convrot_state_dict`：将 state dict 拆分为量化层（weight / weight_scale / groupsize）与 FP16 余量（norm、bias、latents）。
- `install_convrot_linears`：就地替换匹配的 `nn.Linear` 子模块。
- `has_convrot_int8`：sidecar 检测；float 包走原路径不变。

### 3.2 Sidecar 感知载入（`extensions-builtin/sd_forge_ipadapter/lib_ipadapter/IPAdapterPlus.py`）
```python
# IPAdapter.__init__
image_proj_state = ipadapter_model["image_proj"]
if has_convrot_int8(image_proj_state):
    quantized, image_proj_state = split_convrot_state_dict(image_proj_state)
    install_convrot_linears(self.image_proj_model, quantized)
self.image_proj_model.load_state_dict(image_proj_state)

# To_KV.__init__
if has_convrot_int8(state_dict):
    quantized, state_dict = split_convrot_state_dict(state_dict)
    for base, entry in quantized.items():
        self.to_kvs[...] = ConvRotInt8Linear.from_weight(entry["weight"], entry["weight_scale"], entry["groupsize"])
```

### 3.3 运行时 UNet 量化（`modules_forge/hswq_int8.py`）
`_quantize_float_weights_on_the_fly` 通过 `QuantizedTensor.from_float(weight, "TensorWiseINT8Layout")` 量化普通权重，并标记 `quant_format="int8_tensorwise"`。仅在 checkpoint 不含量化元数据时执行，因此量化包的受保护 FP16 层绝不会被重新量化。仅处理可量化模块；非 2D/4D 权重被跳过并报告。

### 3.4 去量化探针保持不动
`ControlNetPatcher.try_build_from_state_dict` 中的无用去量化保持原样（共享路径；每次载入 0.19 秒）。它不影响 IP-Adapter 正确性，因为每个 patcher 接收独立的 state dict 副本。

## 4. 验证与兼容性基准矩阵

所有测试均在配备 **NVIDIA GeForce RTX 5060 Ti (16GB VRAM)** 的 Windows 11 工作站上实测完成：

| 检查点 / 路径 | 精度格式 | 测试结果 |
|---|---|---|
| `ip-adapter_sd15_plus_hswq_convrot_int8.safetensors` | ConvRot INT8 | 54 个 INT8 层（image_proj 22 + ip_adapter 32），`load_state_dict(strict=True)` 成功，每 forward 22 次 `int8_linear` 调用，image embeds 相对 FP16 源的 cosine 0.999526，to_kv 最差 cosine 0.999954，全部 finite。 |
| `ip-adapter_sd15_plus.pth`（float） | FP16 | 原路径不变：0 个 ConvRot INT8 模块，54 个 `nn.Linear`。 |
| UNet `againmix_v22.safetensors` + UI `int8 (fp16 LoRA)` | 运行时 INT8 | 转换 282 个 Conv 层、跳过 0 层；`quantized_tensor_weights=282`；512x512 生成，mean/std 103.9/62.4，近黑像素比 0.0000；相对 FP16 存储路径像素 cosine 1.000000。 |
| Conv2d mock（Linear + Conv2d） | 运行时 INT8 | 存储字节 176,128 → 88,064；cosine 0.999924（Linear）/ 0.999946（Conv2d）；scale dtype float32，orig_dtype float16。 |
