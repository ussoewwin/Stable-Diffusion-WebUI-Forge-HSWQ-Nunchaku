# 版本 2.0.3 — 彻底解决 SDXL ConvRot INT8 黑图/NaN 缺陷与非侵入式 Hadamard 缓存架构优化

本次发布彻底修复了在 `int8` / `int8 (fp16 LoRA)` 模式下载入带有 **ConvRot INT8（逆向混合模式 / reverse hybrid）** 文本编码器的 SDXL 模型时导致输出全黑图像（或潜空间 NaN 崩溃）的严重底层缺陷。同时，在 Forge 内部构建了完全隔离的非侵入式运行时 Hook 架构，在确保不修改任何上游 vendored 子模块的前提下，彻底解决了 Hadamard 矩阵的显存缓存与 GPU 运算优化。

---

## 1. 概述

| 项目 | 详情 |
|---|---|
| **影响范围** | 采用 HSWQ ConvRot INT8 量化格式的 SDXL 模型（包括 Illustrious-XL、Animagine-XL 等 INT8 模型），运行在 `int8` 或 `int8 (fp16 LoRA)` 模式下 |
| **故障表象** | 采样输出全黑图像（Solid Black Image）或潜空间完全崩溃为 NaN；后台终端输出数十条 `CLIPTextModelWithProjection Unexpected: ['transformer.resblocks.*.weight_scale', ...]` 警告 |
| **技术根本原因** | 在 `backend/loader.py` 中，`guess.process_clip_state_dict()` 在执行量化逆运算前便将 CLIP-G（`text_encoder_2`）的 `.weight` 键名从 OpenCLIP 规范强行重命名为 HuggingFace 规范，导致伴随的 `.weight_scale` 与 `.comfy_quant` 元数据未被匹配重命名，使得 OpenCLIP bigG 的 63 个 Linear 层从未执行 Scale 还原与 Hadamard 逆旋转 |
| **修复方案** | 在 `backend/loader.py` 分离 UNet 与 VAE 的 state dict 后、且在调用 `guess.process_clip_state_dict()` 之前，立即就地执行 `dequantize_state_dict_inplace(sd, compute_dtype=...)` |
| **子模块隔离架构** | 彻底撤销对 `modules/ComfyUI-HSWQ-Loader-and-Tools/` 的直接代码修改，在 Forge 专用的 `modules_forge/hswq_int8.py` 中实现运行时 Hook，保证后续上游更新零冲突 |
| **性能实测提升** | 设备级常驻 Hadamard 缓存消除了步进式的 CPU 矩阵生成（Kronecker 递归）与 PCIe Host-to-Device 显存传输开销 |

## 2. 技术背景与根本原因深度剖析

### 2.1 SDXL 双文本编码器架构与量化格式
SDXL 采用了双 Text Encoder 并行架构：
1. **Text Encoder 1 (CLIP ViT-L/14)**：包含 337 个 state_dict 张量，输出 768 维度的 token embedding 序列。
2. **Text Encoder 2 (OpenCLIP ViT-bigG/14)**：包含 644 个 state_dict 张量，输出 1280 维度的 token embedding 序列以及 1280 维度的 pooled projection。

在 HSWQ（Hybrid-Sensitivity-Weighted-Quantization）ConvRot INT8 量化方案中，为了抑制离群激活值（activation outliers），文本编码器内部的所有 Linear 投影层均被量化为 8-bit 整型（`int8_tensorwise`），并通过正交 Hadamard 矩阵进行旋转变换：
$$W_{\text{rot}} = W H^T \quad \Longleftrightarrow \quad W = W_{\text{rot}} H$$

在 safetensors 权重文件中，每个量化层由三个关联的 Key 构成：
- `<layer>.weight`：`torch.int8` 类型的整数张量。
- `<layer>.weight_scale`：Float32 标量（$W_{\text{float}} = W_{\text{int8}} \cdot \text{scale}$）。
- `<layer>.comfy_quant`：包含量化元数据的 JSON 字节串（`{"format": "int8_tensorwise", "convrot": true, "convrot_groupsize": 256}`）。

### 2.2 `backend/loader.py` 中的键名转换脱节故障
在通用的 SDXL safetensors 文件中，Text Encoder 1 采用 HuggingFace 的命名规范（`text_model.encoder.layers.*`），而 Text Encoder 2 采用 OpenAI / OpenCLIP 的原始命名规范（`resblocks.<N>.attn.out_proj.weight`、`resblocks.<N>.mlp.c_fc.weight` 等）。

在 Forge 原有的加载流程中，`backend/loader.py` 执行如下步骤：
```
1. 从 sd 中 pop 出 unet 字典。
2. 从 sd 中 pop 出 vae 字典。
3. 调用 guess.process_clip_state_dict(sd)。
     └─> 触发 clip_text_transformers_convert(sd, prefix="text_encoder_2.")
           └─> 将 'resblocks.<N>.attn.out_proj.weight' 重命名为 'text_model.encoder.layers.<N>.self_attn.out_proj.weight'
4. 实例化 HuggingFace CLIPTextModelWithProjection 并调用 load_state_dict。
```

**故障诱发机理**：
- `clip_text_transformers_convert()` 仅设计用于处理标准的浮点模型，其内部只对以 `.weight` 和 `.bias` 结尾的键名进行重命名模式匹配。
- 对于附带的 `.weight_scale` 和 `.comfy_quant`，该函数完全忽略。
- 结果导致：`resblocks.0.attn.out_proj.weight` 被重命名为 `text_model.encoder.layers.0.self_attn.out_proj.weight`，但其配对的 `resblocks.0.attn.out_proj.weight_scale` 和 `resblocks.0.attn.out_proj.comfy_quant` 却仍然保留在旧的 `resblocks.*` 前缀下。
- 当 HuggingFace 的 `CLIPTextModelWithProjection` 开始装载时，权重矩阵已经失去了元数据支持，所有的 Scale 键均被当作未识别的冗余参数抛弃：
  ```
  CLIPTextModelWithProjection Unexpected: [
    'transformer.resblocks.0.attn.out_proj.weight_scale',
    'transformer.resblocks.0.mlp.c_fc.weight_scale',
    ...
    'transformer.resblocks.31.mlp.c_fc.weight_scale'
  ]
  ```
- 由于未执行 `weight_scale` 反量化乘法，且未执行 Hadamard 逆旋转（$W_{\text{rot}} \times H$），原始的 `int8` 带符号整数值（数值范围为 $-128 \sim +127$）被底层以浮点数半精度（`torch.float16`）直接载入。
- 正常的 FP16 线性层权重数值通常集中在 $[ -0.05, +0.05 ]$。未经 Scale 缩放的权重数值比正常值**放大了 2000 到 2500 倍**，且处于旋转混乱的向量方向。
- CLIP-G 计算出的文本特征张量产生数值爆炸（数值超过 $10^4$）并迅速溢出为 NaN。
- UNet 的 Cross-Attention 模块与溢出的 Conditioning 向量相乘，导致去噪过程中的所有潜变量（Latents）全面崩溃为 NaN。
- VAE 解码器接收到全为非数（NaN）或极大离群值的潜张量，最终解码输出纯黑图像（Solid Black Image）。

## 3. 核心修复方案与完整代码剖析

### 3.1 键名映射前置逆量化（`backend/loader.py`）
根本解决方案在于：必须在键名被 `clip_text_transformers_convert` 打散拆解之前，以原始且完整的命名空间就地完成逆量化与 Hadamard 逆旋转。

在 `backend/loader.py` 的 `split_state_dict()` 中实施前置处理：
```python
    # loader.py (lines 978-992)
    # 此时 UNet 与 VAE 的 state_dict 已被 pop 分离，
    # 当前 sd 中仅保留文本编码器键名（CLIP-L 与 CLIP-G）。
    if memory_management.text_encoder_dtype() is not None:
        try:
            from backend.patch_comfy_quant_layout_fallback import dequantize_state_dict_inplace
            dequant_count = dequantize_state_dict_inplace(sd, compute_dtype=memory_management.text_encoder_dtype())
            if dequant_count > 0:
                logging.info(f"[Forge] Dequantized {dequant_count} ConvRot/INT8 weights to {memory_management.text_encoder_dtype()} prior to CLIP key remapping")
        except Exception as e:
            logging.warning(f"[Forge] text_encoder dequantize_state_dict_inplace skipped: {e}")

    sd = guess.process_clip_state_dict(sd)
```

在此执行时机下：
1. `resblocks.<N>.*.weight` 与 `resblocks.<N>.*.weight_scale` 处在同一命名空间，一一严格对应。
2. CLIP-L（70 个线性层）与 CLIP-G（63 个线性层）均在第一时间被还原为标准的高精度 Float16 张量。
3. 消费完毕的 `.weight_scale` 与 `.comfy_quant` 从 `sd` 中被物理删除。
4. 后续 `guess.process_clip_state_dict(sd)` 在重命名时面对的是纯净的 Float16 权重，`CLIPTextModelWithProjection` 加载时的 **Unexpected keys 彻底归零**。

### 3.2 就地逆量化与 Hadamard 正交逆旋转实现（`backend/patch_comfy_quant_layout_fallback.py`）
在 `backend/patch_comfy_quant_layout_fallback.py` 中实现了通用的就地逆量化处理逻辑：

```python
def dequantize_state_dict_inplace(state_dict: dict, compute_dtype: torch.dtype = torch.float16) -> int:
    """扫描 state_dict 中的 comfy_quant 元数据，原地就地反量化并执行 Hadamard 逆旋转。"""
    quant_keys = [k[:-len(".comfy_quant")] for k in list(state_dict.keys()) if k.endswith(".comfy_quant")]
    if not quant_keys:
        return 0

    dequantized_count = 0
    for prefix in quant_keys:
        meta_raw = state_dict.pop(f"{prefix}.comfy_quant", None)
        w = state_dict.get(f"{prefix}.weight", None)
        s = state_dict.pop(f"{prefix}.weight_scale", None)

        if w is None or s is None:
            continue

        meta = json.loads(meta_raw.numpy().tobytes()) if hasattr(meta_raw, "numpy") else json.loads(meta_raw)
        qformat = meta.get("format")

        if qformat == "int8_tensorwise":
            # 1. 恢复张量实际浮点数值（W_float = W_int8 * scale）
            w_float = w.to(dtype=torch.float32)
            s_float = s.to(dtype=torch.float32)
            if s_float.ndim == 0:
                out = w_float * s_float
            else:
                out = w_float * s_float.reshape(-1, *([1] * (w_float.ndim - 1)))

            # 2. 若存在 ConvRot 旋转标记，执行 Hadamard 逆向旋转
            if meta.get("convrot", False):
                gs = int(meta.get("convrot_groupsize", 256) or 256)
                if out.dim() == 2 and out.shape[1] < gs and (out.shape[1] in (16, 64, 128)):
                    gs = out.shape[1]
                from comfy_kitchen.backends.eager.convrot_w4a4 import _build_hadamard, _rotate_weight
                h = _build_hadamard(gs, device=out.device, dtype=torch.float32)
                # 注：正交归一化 Hadamard 矩阵具备对称正交性（H = H^T，H^{-1} = H）
                out = _rotate_weight(out, h, gs)

            state_dict[f"{prefix}.weight"] = out.to(dtype=compute_dtype)
            dequantized_count += 1

    return dequantized_count
```

### 3.3 无侵入式子模块隔离架构（`modules_forge/hswq_int8.py`）
为了严格遵从项目关于“不得随意修改随上游全量同步的子目录（`modules/ComfyUI-HSWQ-Loader-and-Tools/`）”的规范，所有关于 Hadamard 矩阵的显存缓存与 GPU 运算优化均被抽离至 Forge 自身的封装层（`modules_forge/hswq_int8.py`）中，通过运行时动态 Hook（Monkeypatch）完成挂载：

```python
_HADAMARD_GLOBAL_CACHE: dict[tuple[int, str], object] = {}

def _apply_forge_hadamard_cache_patches() -> None:
    """在运行时挂载 Hadamard 设备级显存缓存 Hook，100% 保持 ComfyUI-HSWQ-Loader-and-Tools 零改动。"""
    import patches.comfy_quant_int8 as cqi

    if not getattr(cqi, "_forge_hadamard_cache_patched", False):
        orig_regular_hadamard = cqi._regular_hadamard_global

        def _cached_regular_hadamard_global(size: int, device=None):
            key = (int(size), str(device))
            cached = _HADAMARD_GLOBAL_CACHE.get(key)
            if cached is not None:
                return cached
            res = orig_regular_hadamard(size, device=device)
            _HADAMARD_GLOBAL_CACHE[key] = res
            return res

        cqi._regular_hadamard_global = _cached_regular_hadamard_global
        cqi._forge_hadamard_cache_patched = True

    try:
        nc = cqi._load_native_convert_int8_helpers()
        if nc is not None and not getattr(nc, "_forge_unrotate_conv2d_patched", False):
            orig_unrotate_conv2d = nc.unrotate_weight_conv2d

            def _device_cached_unrotate_weight_conv2d(weight, h_matrix, group_size: int):
                # 当权重处于 CUDA 显存时，避免每步采样都将 CPU 上的 h_matrix 重新传输至显存
                if getattr(weight, "device", None) is not None and (
                    getattr(h_matrix, "device", None) != weight.device
                    or getattr(h_matrix, "dtype", None) != weight.dtype
                ):
                    h_matrix = nc.get_hadamard_on_device(
                        int(group_size), device=weight.device, dtype=weight.dtype
                    )
                return orig_unrotate_conv2d(weight, h_matrix, group_size)

            nc.unrotate_weight_conv2d = _device_cached_unrotate_weight_conv2d
            nc._forge_unrotate_conv2d_patched = True
    except Exception as exc:
        _plog(f"warn: _apply_forge_hadamard_cache_patches nc hook skipped: {exc}")
```

该架构的技术优势：
1. **上游完全解耦**：`modules/ComfyUI-HSWQ-Loader-and-Tools` 保持纯净，上游仓库 `git pull` 或全量更新覆盖时绝不产生代码冲突。
2. **极速热加载与零重复开销**：Hadamard 矩阵仅在首次用到指定 `(group_size, device)` 时生成一次，后续整个生命周期内直接命中缓存。
3. **消除 Host-to-Device 显存瓶颈**：矩阵常驻目标显卡，消除了 Conv2d 在线 LoRA 烘焙时的每步 PCIe 总线通信开销。
