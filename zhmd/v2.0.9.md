# 版本 2.0.9 — IP-Adapter 条件注入不再与 Token Merging (ToMeSD) 冲突崩溃

本次发布修复了当 IP-Adapter ConvRot INT8 与 Token Merging (ToMeSD) 同时启用时，在第二次及后续生成中抛出 `RuntimeError: The expanded size of the tensor (3786) must match the existing size (8112)` 的崩溃。通过限定 `transformer_options` 的转发范围，使 ToMeSD 的 `attn1_patch` 家族不再被送入 SD 1.5 UNet forward，同时保持 IP-Adapter 条件注入完全生效（512x512 下 weight 0.6 与 0.0 的像素 cosine 为 0.880120）。

---

## 1. 概述

| 项目 | 详情 |
|---|---|
| **影响范围** | 在 UI Low Bits `int8` / `int8 (fp16 LoRA)` 选项下载入的 SD 1.5（及 SD 1.5 变体）checkpoint，同时启用 Token Merging（`token_merging_ratio > 0`）与 IP-Adapter ConvRot INT8 (HSWQ) 单元。 |
| **故障表象** | 1. **第二次生成崩溃**：在 `backend/misc/tomesd.py`（`bipartite_soft_matching_random2d`）内抛出 `RuntimeError: The expanded size of the tensor (3786) must match the existing size (8112) at non-singleton dimension 1`，中止第二次及后续所有生成。<br>2. **首次生成正常**：首次生成完成且 IP-Adapter 条件注入已生效；崩溃仅从第二次生成开始出现。 |
| **技术根本原因** | `modules/sd_models.py` 中的 `apply_token_merging` 每次生成都调用 `TomePatcher.patch`，后者克隆模型 patcher（复制已注册的 patch）后再次 `set_model_attn1_patch` 追加 `tomesd_m`。从第二次生成起，`attn1_patch` 中包含重复的 `tomesd_m`。v2.0.8 的修复首次将 `transformer_options`（含 `attn1_patch` / ToMeSD 家族）送入 SD 1.5 UNet forward，从而使重复的 ToMeSD 回调首次执行，对同一张量执行了两次 token 合并。 |
| **核心架构解决方案** | 1. **限定范围的 `transformer_options` 转发**：`backend/modules/k_model.py` 现仅在存在 `patches_replace`（IP-Adapter 及同类 attn-replace patch）时才将 `transformer_options` 转发给 SD 1.5 UNet，并从中剔除 `patches`（attn1_patch）家族。ToMeSD 在此路径上保持原有行为。<br>2. **分离（分離・分支）**：IP-Adapter attn-replace 与 ToMeSD attn1 patch 是独立关注点；只有前者需要送入 UNet forward。 |
| **性能实测提升** | 连续生成不再崩溃；IP-Adapter weight 0.6 下 512x512 生成约 1.47s/it；832x832（用户分辨率）生成完成。IP-Adapter 条件注入对图像产生可测量影响（512x512 下 weight 0.6 与 0.0 的像素 cosine 0.880120）。 |

---

## 2. 技术背景与根本原因深度剖析

### 2.1 Token Merging 累积
`modules/sd_models.py` 中的 `apply_token_merging`（第 305 行）每次生成都调用 `TomePatcher.patch(model=sd_model.forge_objects.unet, ratio=token_merging_ratio)`。`TomePatcher.patch` 调用 `model.clone()`，后者复制已注册的 patch 列表，随后 `set_model_attn1_patch(tomesd_m)` 追加新条目。从第二次生成起，`attn1_patch` 中包含重复的 `tomesd_m` 回调。

### 2.2 为何仅在 v2.0.8 中暴露
在 v2.0.8 之前，`backend/modules/k_model.py` 并未将 `transformer_options` 送入 SD 1.5 UNet forward，因此 `attn1_patch`（ToMeSD）被注册但从未消费——实质上是死代码。v2.0.8 为了使 IP-Adapter 的 `patches_replace` 能送入 forward 而转发了 `transformer_options`，同时也首次执行了重复的 ToMeSD 回调。

### 2.3 数值不匹配
首次 ToMeSD 合并将 token 数从 10816 降至 6490（`6490 = 10816 - int(10816 * 0.4)`）。第二次（重复）合并重新计算 `downsample = int(ceil(sqrt(10816 // 6490))) = 1`，`num_dst = (104 // 1) ** 2 = 10816` 超出可用 src token 数，产生 `expand(1, 6490 - 2704, 320) = [1, 3786, 320]` 与 `a_idx [1, 8112, 1]` 的不匹配——与日志中报告的 `RuntimeError: The expanded size of the tensor (3786) must match the existing size (8112)` 完全一致。

## 3. 核心修复方案与完整代码剖析

### 3.1 限定范围的转发（`backend/modules/k_model.py`）
```python
elif "patches_replace" in (transformer_options or {}):
    # IP-Adapter (attn2 patches_replace) needs transformer_options to reach the
    # UNet forward; otherwise patches_replace is registered but never consumed
    # and the conditioning has no effect on the generated image.
    # "patches" (attn1_patch family, e.g. ToMeSD token merging) stays excluded:
    # this forward never consumed it before, and ToMeSD re-registers its patch
    # every generation, so passing it would merge tokens twice into the same
    # tensor and crash (backend/misc/tomesd.py size mismatch).
    forward_options = {k: v for k, v in (transformer_options or {}).items() if k != "patches"}
    model_output = self.diffusion_model(xc, t, context=context, control=control, transformer_options=forward_options, **extra_conds_clean).float()
```
仅 `patches_replace`（IP-Adapter）送入 forward；`patches`（ToMeSD）被剔除，ToMeSD 保持原有死代码行为（输出无变化）。

## 4. 验证与兼容性基准矩阵

所有测试均在配备 **NVIDIA GeForce RTX 5060 Ti (16GB VRAM)** 的 Windows 11 工作站上实测完成，checkpoint 为 `againmix_v22.safetensors`（FP16），IP-Adapter 为 `ip-adapter_sd15_plus_hswq_convrot_int8`：

| 场景 | 测试结果 |
|---|---|
| Plain 512x512（无 IP-Adapter） | mean 106.0 / std 62.1 — 正常生成，与修复前完全一致。 |
| IP-Adapter weight 0.6，512x512，连续三次生成 | 全部完成；无崩溃（修复前第二次生成即崩溃）。 |
| IP-Adapter weight 0.6 vs 0.0，512x512 | 像素 cosine 0.880120，mean\|diff\| 61.23 — 条件注入对图像产生可测量影响。 |
| IP-Adapter weight 0.6，832x832（用户分辨率），连续两次生成 | 两次均完成，无崩溃。 |
