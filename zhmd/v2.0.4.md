# 版本 2.0.4 — Anima compute_qkv transformer_options 兼容修复与 ControlNet ConvRot INT8 bfloat16 去量化

本次发布修复了使用 Anima 模型生成时在第一个降噪步骤即触发的硬崩溃（Forge 侧 Q/K RMSNorm + 半分 RoPE 融合补丁的签名过旧所致），并修复了 bfloat16 ControlNet 检查点经 ConvRot INT8 回退路径去量化时被静默降级为 fp16 的问题，同时加固了量化模型构建过程以避开 inference mode 记账错误。

---

## 1. 概述

| 项目 | 详情 |
|---|---|
| **影响范围** | Anima 模型（Cosmos Predict2 `Anima` DiT，例如 `waiANIMA_v10Base10.safetensors`）在安装了 RoPE 融合补丁的 `comfy.ldm.cosmos.predict2.Attention.compute_qkv` 下运行时；以及以 ConvRot INT8 格式分发、激活为 bfloat16 的 ControlNet 模型 |
| **故障表象** | 采样在 `0/32` 步即中止，报 `TypeError: _patched_compute_qkv() got an unexpected keyword argument 'transformer_options'`；ControlNet 检查点经回退路径去量化后，无论检查点自身计算 dtype 是什么都被写成 fp16 |
| **技术根本原因** | 上游 `Attention.forward` 现在总是向 `compute_qkv` 传入 `transformer_options=`，而 Forge 侧融合补丁仍使用旧的三参数签名。回退去量化路径只携带 fp16 的 dtype code，并把所有目标张量默认为 fp16 |
| **修复方案（`backend/nn/comfy_anima.py`）** | `_patched_compute_qkv` 接受 `transformer_options: Optional[dict] = None`。融合逻辑忽略该参数；SelfAttn+RoPE 融合分支与原版 CrossAttn 路径完全不变 |
| **其他修复** | `dequantize_state_dict_inplace` 自动检测 bf16/fp16，使用原生 bf16 去量化内核（`code=2`），并按设备缓存 Hadamard 矩阵；标准 ControlNet 与 Qwen Image Fun ControlNet 在构建前对 INT8 state dict 去量化；Qwen Fun 模型同步到扩散模型的设备与浮点 dtype；MixedPrecision（Krea2）与 ConvRot INT8 构建在禁用 inference mode 下运行；Comfy 原生的 Anima/Krea2 文本编码器跳过预去量化，使 `comfy_quant` 布局原生加载 |
| **性能实测提升** | Hadamard 矩阵按 `(group_size, device)` 对构建一次并常驻缓存，旋转在可用时于 CUDA 上执行，把去量化收敛为每权重一次 device-to-host 传输 |

## 2. 技术背景与根本原因深度剖析

### 2.1 Forge 侧 RoPE 融合补丁与上游调用契约
Anima 的 Q/K RMSNorm + 半分 RoPE 融合（v1.8.3 引入）在加载时通过 `backend/nn/comfy_anima.py` 的 `install_anima_rms_rope_fuse()` 替换 `comfy.ldm.cosmos.predict2.Attention.compute_qkv`。融合补丁把 Q/K RMSNorm 缩放与半分 RoPE 旋转合并为一次 `comfy_kitchen.rms_rope_split_half` 调用（仅 SelfAttn+RoPE 路径），其余路径（CrossAttn、无 RoPE）保持原版实现。

Forge 所用的内嵌 ComfyUI 树（`ComfyUI-master/comfy/ldm/cosmos/predict2.py`）随上游演进。在融合补丁引入之后的某个时点，`Attention.forward` 采用了新的调用契约：

```python
q, k, v = self.compute_qkv(x, context, rope_emb=rope_emb, transformer_options=transformer_options)
```

融合补丁早于该契约，仍携带旧的三参数签名，因此每次 Anima 生成都会在第一个 `SelfAttn` 块调用时立即崩溃。

### 2.2 故障机制（完整 traceback）
崩溃表面出现在 RES4LYF beta 采样器内，但根源是被补丁的方法：

```text
File "...comfy/ldm/cosmos/predict2.py", line 220, in forward
    q, k, v = self.compute_qkv(x, context, rope_emb=rope_emb, transformer_options=transformer_options)
TypeError: _patched_compute_qkv() got an unexpected keyword argument 'transformer_options'
```

调用链为：`txt2img` 采样 → `calc_cond_uncond_batch` → `apply_model` → `predict2._forward` 块循环 → `SelfAttn.forward` → `compute_qkv`。由于被补丁的 `compute_qkv` 在模型加载时即安装，模型首次前向传播就命中该不匹配，在任何一个降噪步骤完成之前就已崩溃。

### 2.3 ControlNet ConvRot INT8 的 dtype 缺口
`dequantize_state_dict_inplace` 通过原生 `comfy_kitchen` 内核对 ConvRot INT8 张量去量化，使用 dtype code（fp16 → `1`，fp32 → `0`）。bfloat16 检查点需要 code `2`，而回退路径从未传入；fp16 默认值把 bf16 ControlNet 权重静默地经 fp16 转写，且 fp16 的 Hadamard 矩阵缓存造成每权重一次 host-to-GPU 往返。

## 3. 核心修复方案与完整代码剖析

### 3.1 `_patched_compute_qkv` 签名加固（`backend/nn/comfy_anima.py`）
被补丁方法现在暴露与原版实现相同的调用面：

```python
def _patched_compute_qkv(
    self,
    x,
    context: Optional[object] = None,
    rope_emb: Optional[object] = None,
    transformer_options: Optional[dict] = None,
):
```

该参数被接受且被忽略：融合逻辑不基于它做任何分支，因此 SelfAttn+RoPE 的融合数学、`q_norm`/`k_norm` 的 scale cast 行为、以及原版 CrossAttn/无 RoPE 路径与 v2.0.3 逐字节一致。

### 3.2 就地去量化的 bf16 支持（`backend/patch_comfy_quant_layout_fallback.py`）
- `dequantize_state_dict_inplace` 不再强制要求显式 `compute_dtype`：省略时取 state dict 中首个 `bfloat16` / `float16` 张量的 dtype，仅在其他都不可用时回退 fp16。
- 原生 CUDA 内核可达时，dtype code 现为 fp16 → `1`、bf16 → `2`，结果在设备上完成 cast 后仅做一次 `.cpu()` 传输。
- Hadamard 缓存按 `(group_size, device)` 为键，CPU 张量与 CUDA 张量在各自设备维护独立缓存矩阵，不再逐权重重建。
- 无量化层存在时，CUDA synchronize 之后追加 `torch.cuda.empty_cache()` 以释放暂存分配。

### 3.3 ControlNet 加载器整合
- `modules_forge/supported_controlnet.py`：`ControlNetPatcher.try_build_from_state_dict` 先执行 `dequantize_state_dict_inplace(controlnet_data)`，使 ConvRot INT8 ControlNet 在任何 marker 检查或模型构建之前就去量化到检查点自身的计算 dtype。
- `modules_forge/supported_controlnet_qwen_fun.py`：`_build_comfyui_fun_model` 在形状探测前把 state dict 去量化为 bf16；`QwenFunControlNetPatcher.process` 把构建好的 Fun 模型移动到扩散模型的设备**与**浮点 dtype（bf16/fp16/fp32），替换了此前仅移动设备、可能在 ControlNet 栈与 UNet 之间留下 dtype 不匹配的实现。

### 3.4 Comfy 原生文本编码器加载与量化构建加固
- `backend/loader.py` 的 `split_state_dict` 对 Comfy 原生文本编码器跳过预去量化：Krea2 与 Anima 猜测路径，以及 CLIP target 为 `qwen3vl_4b`、`qwen3_4b`、`qwen3_06b`、`gemma2_2b` 的检查点，现在保持 `comfy_quant` 布局完整，由原生 Comfy ops 直接加载。
- `backend/loader.py` 的 `load_huggingface_component` 在实例化前把 TE state dict 去量化到组件自身的 storage dtype，并为 `Lumina2Transformer2DModel`、`ZImageTransformer2DModel`、`SingleStreamDiT`、`CosmosTransformer3DModel` 显式设置 `unet_config["dtype"]`。
- MixedPrecision（Krea2）与 ConvRot INT8 分支在 `torch.inference_mode(False), torch.no_grad()` 下构建模型，使量化构建期间的参数改写不会触发 inference tensor 记账错误。
