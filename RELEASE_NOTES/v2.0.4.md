# Version 2.0.4 — Anima compute_qkv Transformer Options Compatibility & ControlNet ConvRot INT8 bfloat16 Dequantization

This release resolves a hard crash at the very first denoising step when generating with Anima checkpoints under the Forge-side Q/K RMSNorm + split-half RoPE fuse. It also fixes ControlNet ConvRot INT8 loading for bfloat16 checkpoints by extending the in-place dequantization fallback with native bf16 support, and hardens quantized model construction against inference-mode bookkeeping errors.

---

## 1. Executive Summary

| Item | Detail |
|---|---|
| **Affected Scope** | Anima checkpoints (Cosmos Predict2 `Anima` DiT, e.g. `waiANIMA_v10Base10.safetensors`) when the RoPE fuse patch on `comfy.ldm.cosmos.predict2.Attention.compute_qkv` is installed; ControlNet models shipped as ConvRot INT8 with bfloat16 activations |
| **Symptom** | Sampling aborts at `0/32` steps with `TypeError: _patched_compute_qkv() got an unexpected keyword argument 'transformer_options'`; ControlNet checkpoints dequantized through the fallback path landed in fp16 regardless of the checkpoint's compute dtype |
| **Root Cause** | Upstream `Attention.forward` now always passes `transformer_options=` into `compute_qkv`, while the Forge-side fuse patch still used the old three-argument signature. The fallback dequantization path only carried an fp16 dtype code and defaulted every target tensor to fp16. |
| **Fix in `backend/nn/comfy_anima.py`** | `_patched_compute_qkv` accepts `transformer_options: Optional[dict] = None`. The fuse ignores the kwarg; the SelfAttn+RoPE fuse branch and the stock CrossAttn path are unchanged. |
| **Additional Fixes** | `dequantize_state_dict_inplace` auto-detects bf16/fp16, uses the native bf16 dequantization kernel (`code=2`), and caches Hadamard matrices per device; standard ControlNet and Qwen Image Fun ControlNet dequantize INT8 state dicts before construction; Qwen Fun models sync to the diffusion model's device and floating-point dtype; MixedPrecision (Krea2) and ConvRot INT8 model construction runs with inference mode disabled; Comfy-native Anima/Krea2 text encoders skip pre-dequantization so `comfy_quant` layouts load natively |
| **Performance Impact** | Hadamard matrices are constructed once per `(group_size, device)` pair and rotation runs on CUDA when available, collapsing dequantization to a single device-to-host transfer per weight |

## 2. Technical Background & Root Cause Analysis

### 2.1 Forge-Side RoPE Fuse Patch & Upstream Call Contract
The Anima Q/K RMSNorm + split-half RoPE fuse (introduced in v1.8.3) replaces `comfy.ldm.cosmos.predict2.Attention.compute_qkv` at load time via `install_anima_rms_rope_fuse()` in `backend/nn/comfy_anima.py`. The fuse fuses the Q/K RMSNorm scales with the split-half RoPE rotation into a single `comfy_kitchen.rms_rope_split_half` call on the SelfAttn+RoPE path, and leaves every other path (CrossAttn, no-RoPE) on the stock implementation.

The vendored ComfyUI tree used by Forge (`ComfyUI-master/comfy/ldm/cosmos/predict2.py`) evolves with upstream. At some point after the fuse was introduced, `Attention.forward` learned a new calling contract:

```python
q, k, v = self.compute_qkv(x, context, rope_emb=rope_emb, transformer_options=transformer_options)
```

The fuse patch predates this contract and still carried the old three-argument signature, so every Anima generation crashed on the very first `SelfAttn` block invocation.

### 2.2 The Failure Mechanism (Exact Traceback)
The crash surfaces inside the RES4LYF beta sampler but its origin is the patched method:

```text
File "...comfy/ldm/cosmos/predict2.py", line 220, in forward
    q, k, v = self.compute_qkv(x, context, rope_emb=rope_emb, transformer_options=transformer_options)
TypeError: _patched_compute_qkv() got an unexpected keyword argument 'transformer_options'
```

The call chain is: `txt2img` sampling → `calc_cond_uncond_batch` → `apply_model` → `predict2._forward` block loop → `SelfAttn.forward` → `compute_qkv`. Because the patched `compute_qkv` was installed once at model load, the first forward pass of the model hit the mismatch immediately, before a single denoising step completed.

### 2.3 ControlNet ConvRot INT8 dtype Gap
`dequantize_state_dict_inplace` dequantizes ConvRot INT8 tensors through the native `comfy_kitchen` kernel using a dtype code (fp16 → `1`, fp32 → `0`). bfloat16 checkpoints need code `2`, which the fallback path never passed; the fp16 default silently cast bf16 ControlNet weights through fp16, and the fp16 Hadamard-matrix cache caused a per-weight host-to-GPU roundtrip.

## 3. Implementation Details & Code Walkthrough

### 3.1 `_patched_compute_qkv` Signature Hardening (`backend/nn/comfy_anima.py`)
The patched method now exposes the same surface as the stock implementation:

```python
def _patched_compute_qkv(
    self,
    x,
    context: Optional[object] = None,
    rope_emb: Optional[object] = None,
    transformer_options: Optional[dict] = None,
):
```

The kwarg is accepted and ignored: the fuse performs no branching on it, so the SelfAttn+RoPE fused math, the scale-cast behavior of `q_norm`/`k_norm`, and the stock CrossAttn/no-RoPE paths are byte-for-byte unchanged from v2.0.3.

### 3.2 In-Place Dequantization bf16 Support (`backend/patch_comfy_quant_layout_fallback.py`)
- `dequantize_state_dict_inplace` no longer requires an explicit `compute_dtype`: when omitted, it takes the dtype of the first `bfloat16` / `float16` tensor found in the state dict, falling back to fp16 only when nothing else is available.
- When the native CUDA kernel is reachable, the dtype code is now `1` for fp16 and `2` for bf16, and the result is cast on device before a single `.cpu()` transfer.
- The Hadamard cache is keyed by `(group_size, device)`, so CPU tensors and CUDA tensors maintain separate cached matrices at their own device instead of re-building them per weight.
- When no quantized layers were present, a `torch.cuda.empty_cache()` follows the CUDA synchronize to release scratch allocations.

### 3.3 ControlNet Loader Integration
- `modules_forge/supported_controlnet.py`: `ControlNetPatcher.try_build_from_state_dict` runs `dequantize_state_dict_inplace(controlnet_data)` first, so a ConvRot INT8 ControlNet is dequantized to its checkpoint's compute dtype before any marker inspection or model construction.
- `modules_forge/supported_controlnet_qwen_fun.py`: `_build_comfyui_fun_model` dequantizes the state dict to bf16 before shape probing, and `QwenFunControlNetPatcher.process` moves the built Fun model to the diffusion model's device *and* floating-point dtype (bf16/fp16/fp32), replacing the earlier device-only move that could leave a dtype mismatch between the ControlNet stack and the UNet.

### 3.4 Comfy-Native Text Encoder Loading & Quantized Construction Hardening
- `backend/loader.py` `split_state_dict` skips the pre-dequantization pass for Comfy-native text encoders: Krea2 and Anima guess paths, and any checkpoint whose CLIP target is `qwen3vl_4b`, `qwen3_4b`, `qwen3_06b`, or `gemma2_2b`, now keep their `comfy_quant` layout intact so the native Comfy ops load them directly.
- `backend/loader.py` `load_huggingface_component` dequantizes the TE state dict to the component's own storage dtype before instantiation, and sets `unet_config["dtype"]` explicitly for `Lumina2Transformer2DModel`, `ZImageTransformer2DModel`, `SingleStreamDiT`, and `CosmosTransformer3DModel`.
- MixedPrecision (Krea2) and ConvRot INT8 branches construct the model under `torch.inference_mode(False), torch.no_grad()`, so parameter rewriting during quantized construction does not hit inference-tensor bookkeeping errors.
