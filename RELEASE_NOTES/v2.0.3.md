# Version 2.0.3 — Resolution of SDXL ConvRot INT8 Black Images & Non-Invasive Hadamard Cache Architecture

This release resolves a critical bug causing solid black images (or NaN latent collapse) when loading SDXL checkpoints with **ConvRot INT8 (reverse hybrid)** text encoders under `int8` / `int8 (fp16 LoRA)`. It also introduces a non-invasive runtime monkeypatch architecture in Forge that avoids modifying vendored submodules while optimizing Hadamard matrix caching and GPU execution.

---

## 1. Executive Summary

| Item | Detail |
|---|---|
| **Affected Scope** | SDXL checkpoints using HSWQ ConvRot INT8 (`int8` / `int8 (fp16 LoRA)`), including Illustrious-XL and Animagine-XL INT8 models |
| **Symptom** | Denoising produced solid black images (or completely blown-out NaN latents); terminal logged dozens of `CLIPTextModelWithProjection Unexpected: ['transformer.resblocks.*.weight_scale', ...]` warnings |
| **Root Cause** | In `backend/loader.py`, `guess.process_clip_state_dict()` remapped CLIP-G (`text_encoder_2`) `.weight` keys from OpenCLIP to HuggingFace format *before* dequantization, leaving `.weight_scale` and `.comfy_quant` unmatched. CLIP-G's 63 rotated linear layers were never unscaled or unrotated. |
| **Fix in `backend/loader.py`** | Added `dequantize_state_dict_inplace(sd, compute_dtype=...)` immediately after splitting UNet and VAE state dicts and *before* `guess.process_clip_state_dict()` runs. |
| **Submodule Isolation** | Reverted all direct edits in `modules/ComfyUI-HSWQ-Loader-and-Tools/patches/comfy_quant_int8.py` and implemented runtime monkeypatching in `modules_forge/hswq_int8.py`. |
| **Performance Impact** | Device-cached Hadamard unrotation eliminates step-by-step CPU matrix regeneration and PCIe host-to-device transfers. |

## 2. Technical Background & Root Cause Analysis

### 2.1 SDXL Dual Text Encoder Architecture & Quantization Format
SDXL utilizes two separate text encoders operating concurrently:
1. **Text Encoder 1 (CLIP ViT-L/14)**: 337 state_dict tensors, outputting a 768-dimensional token embedding sequence.
2. **Text Encoder 2 (OpenCLIP ViT-bigG/14)**: 644 state_dict tensors, outputting a 1280-dimensional token embedding sequence and a 1280-dimensional pooled projection.

Under HSWQ (Hybrid-Sensitivity-Weighted-Quantization) ConvRot INT8, all linear projections within both text encoders are quantized to 8-bit integers (`int8_tensorwise`) and rotated using orthogonal Hadamard matrices to suppress activation outliers:
$$W_{\text{rot}} = W H^T \quad \Longleftrightarrow \quad W = W_{\text{rot}} H$$

In safetensors checkpoints, each quantized layer is represented by three keys:
- `<layer>.weight`: Tensor of dtype `torch.int8`.
- `<layer>.weight_scale`: Float32 per-tensor scale factor ($W_{\text{float}} = W_{\text{int8}} \cdot \text{scale}$).
- `<layer>.comfy_quant`: Serialized JSON metadata containing format properties (`"format": "int8_tensorwise", "convrot": true, "convrot_groupsize": 256`).

### 2.2 The Key Remapping Collision in `backend/loader.py`
In standard SDXL checkpoints, Text Encoder 1 is saved using HuggingFace naming (`text_model.encoder.layers.*`), while Text Encoder 2 is saved using OpenAI / OpenCLIP naming (`resblocks.<N>.attn.out_proj.weight`, `resblocks.<N>.mlp.c_fc.weight`, etc.).

During model loading in `backend/loader.py`, the following sequence occurred:
```
1. UNet state dict popped from sd.
2. VAE state dict popped from sd.
3. guess.process_clip_state_dict(sd) called.
     └─> calls clip_text_transformers_convert(sd, prefix="text_encoder_2.")
           └─> Renames 'resblocks.<N>.attn.out_proj.weight' to 'text_model.encoder.layers.<N>.self_attn.out_proj.weight'
4. HuggingFace CLIPTextModelWithProjection instantiated and loaded.
```

**The Failure Mechanism**:
- `clip_text_transformers_convert()` is hardcoded to recognize and rename only standard tensor attributes: `.weight` and `.bias`.
- It completely ignored `.weight_scale` and `.comfy_quant` keys!
- Therefore, `resblocks.0.attn.out_proj.weight` was renamed to `text_model.encoder.layers.0.self_attn.out_proj.weight`, but `resblocks.0.attn.out_proj.weight_scale` and `resblocks.0.attn.out_proj.comfy_quant` remained unchanged under the old `resblocks.*` prefix.
- When `CLIPTextModelWithProjection` was loaded, the model could not find any quantization scale or metadata matching `text_model.encoder.layers.0.self_attn.out_proj`.
- All 63 scale keys were flagged as `Unexpected keys` and discarded:
  ```
  CLIPTextModelWithProjection Unexpected: [
    'transformer.resblocks.0.attn.out_proj.weight_scale',
    'transformer.resblocks.0.mlp.c_fc.weight_scale',
    ...
    'transformer.resblocks.31.mlp.c_fc.weight_scale'
  ]
  ```
- Without `weight_scale` and without the Hadamard unrotation pass ($W_{\text{rot}} \times H$), raw `int8` signed integer values (ranging from $-128$ to $+127$) were directly interpreted as half-precision floats (`torch.float16`).
- Because typical FP16 weights have magnitudes in the range $[ -0.05, +0.05 ]$, the unscaled weights were **2000× to 2500× larger** than normal, with arbitrary rotated vector directions.
- The resulting text embeddings exploded into astronomical values ($> 10^4$) and NaN.
- The UNet Cross-Attention matrices multiplied by NaN conditioning vectors, propagating zeros/NaNs through all latent layers.
- The VAE decoder received corrupted latents and decoded a completely solid black image.

## 3. Implementation Details & Code Walkthrough

### 3.1 Pre-Remap In-Place Dequantization (`backend/loader.py`)
To prevent key remapping collisions, dequantization and Hadamard unrotation must take place while the original checkpoint state dict keys are still intact.

In `backend/loader.py`, inside `split_state_dict()`:
```python
    # loader.py (lines 978-992)
    # UNet and VAE state dicts are already popped:
    # sd now contains ONLY text encoder keys (CLIP-L and CLIP-G).
    if memory_management.text_encoder_dtype() is not None:
        try:
            from backend.patch_comfy_quant_layout_fallback import dequantize_state_dict_inplace
            dequant_count = dequantize_state_dict_inplace(sd, compute_dtype=memory_management.text_encoder_dtype())
            if dequant_count > 0:
                logging.info(f"[Forge] Dequantized {dequant_count} ConvRot/INT8 weights to {memory_management.text_encoder_dtype()} prior to CLIP key remapping")
        except Exception as e:
            logging.warning(f"[Forge] text_encoder dequantize_state_dict_inplace skipped: {e}")

    sd = guess.process_clip_state_dict(sd)
```

By invoking `dequantize_state_dict_inplace(sd)` before `guess.process_clip_state_dict(sd)`:
1. `resblocks.<N>.*.weight` and `resblocks.<N>.*.weight_scale` are perfectly co-located.
2. Both CLIP-L (70 linear layers) and CLIP-G (63 linear layers) are reconstructed into pure Float16 tensors.
3. All `.weight_scale` and `.comfy_quant` entries are safely removed from the state dict.
4. When `guess.process_clip_state_dict(sd)` subsequently renames the keys, it operates on standard Float16 weights, and `CLIPTextModelWithProjection` loads with **zero Unexpected keys**.

### 3.2 In-Place Dequantization & Hadamard Inverse Rotation (`backend/patch_comfy_quant_layout_fallback.py`)
`dequantize_state_dict_inplace` handles both tensor-wise scale multiplication and group-wise Hadamard inverse transformation:

```python
def dequantize_state_dict_inplace(state_dict: dict, compute_dtype: torch.dtype = torch.float16) -> int:
    """Scan state_dict for comfy_quant metadata, dequantize and unrotate in-place."""
    quant_keys = [k[:-len(".comfy_quant")] for k in list(state_dict.keys()) if k.endswith(".comfy_quant")]
    if not quant_keys:
        return 0

    dequantized_count = 0
    for prefix in quant_keys:
        meta_raw = state_dict.pop(f"{prefix}.comfy_quant", None)
        w = state_dict.get(f"{prefix}.weight", None)
        s = state_dict.pop(f"{prefix}.weight_scale", None)

        if w is None or s is None:
            continue

        meta = json.loads(meta_raw.numpy().tobytes()) if hasattr(meta_raw, "numpy") else json.loads(meta_raw)
        qformat = meta.get("format")

        if qformat == "int8_tensorwise":
            # 1. Scale integer weights to floating point
            w_float = w.to(dtype=torch.float32)
            s_float = s.to(dtype=torch.float32)
            if s_float.ndim == 0:
                out = w_float * s_float
            else:
                out = w_float * s_float.reshape(-1, *([1] * (w_float.ndim - 1)))

            # 2. Reverse Hadamard rotation if convrot is flagged
            if meta.get("convrot", False):
                gs = int(meta.get("convrot_groupsize", 256) or 256)
                if out.dim() == 2 and out.shape[1] < gs and (out.shape[1] in (16, 64, 128)):
                    gs = out.shape[1]
                from comfy_kitchen.backends.eager.convrot_w4a4 import _build_hadamard, _rotate_weight
                h = _build_hadamard(gs, device=out.device, dtype=torch.float32)
                # Note: H is symmetric and orthogonal (H^T = H, H^{-1} = H)
                out = _rotate_weight(out, h, gs)

            state_dict[f"{prefix}.weight"] = out.to(dtype=compute_dtype)
            dequantized_count += 1

    return dequantized_count
```

### 3.3 Non-Invasive Submodule Isolation (`modules_forge/hswq_int8.py`)
To adhere strictly to project rules preventing modification of vendored code (`modules/ComfyUI-HSWQ-Loader-and-Tools`), all caching optimizations were extracted into a runtime monkeypatch located in Forge's own codebase (`modules_forge/hswq_int8.py`):

```python
_HADAMARD_GLOBAL_CACHE: dict[tuple[int, str], object] = {}

def _apply_forge_hadamard_cache_patches() -> None:
    """Runtime monkeypatch for Hadamard device caching without modifying ComfyUI-HSWQ-Loader-and-Tools."""
    import patches.comfy_quant_int8 as cqi

    if not getattr(cqi, "_forge_hadamard_cache_patched", False):
        orig_regular_hadamard = cqi._regular_hadamard_global

        def _cached_regular_hadamard_global(size: int, device=None):
            key = (int(size), str(device))
            cached = _HADAMARD_GLOBAL_CACHE.get(key)
            if cached is not None:
                return cached
            res = orig_regular_hadamard(size, device=device)
            _HADAMARD_GLOBAL_CACHE[key] = res
            return res

        cqi._regular_hadamard_global = _cached_regular_hadamard_global
        cqi._forge_hadamard_cache_patched = True

    try:
        nc = cqi._load_native_convert_int8_helpers()
        if nc is not None and not getattr(nc, "_forge_unrotate_conv2d_patched", False):
            orig_unrotate_conv2d = nc.unrotate_weight_conv2d

            def _device_cached_unrotate_weight_conv2d(weight, h_matrix, group_size: int):
                # Avoid repeatedly transferring CPU h_matrix to CUDA on each step
                if getattr(weight, "device", None) is not None and (
                    getattr(h_matrix, "device", None) != weight.device
                    or getattr(h_matrix, "dtype", None) != weight.dtype
                ):
                    h_matrix = nc.get_hadamard_on_device(
                        int(group_size), device=weight.device, dtype=weight.dtype
                    )
                return orig_unrotate_conv2d(weight, h_matrix, group_size)

            nc.unrotate_weight_conv2d = _device_cached_unrotate_weight_conv2d
            nc._forge_unrotate_conv2d_patched = True
    except Exception as exc:
        _plog(f"warn: _apply_forge_hadamard_cache_patches nc hook skipped: {exc}")
```

This architecture achieves:
1. **Zero Upstream Drift**: `modules/ComfyUI-HSWQ-Loader-and-Tools` remains completely untouched. Upstream updates (`git pull` / folder copy) will never conflict or overwrite Forge modifications.
2. **Instant Warm-Up**: Hadamard matrices are constructed once per `(group_size, device)` pair and cached for the remainder of the process lifetime.
3. **Elimination of Host-to-Device Bottlenecks**: Matrices remain resident on the target GPU, eliminating per-step PCIe traffic during Conv2d online LoRA unrotation.
