# Version 2.0.7 — ControlNet ConvRot INT8 Loading & Precision Synchronization Architecture

This release resolves the critical initialization failure, floating-point gradient errors (`RuntimeError: Only Tensors of floating point and complex dtype can require gradients`), and compute dtype mismatches when loading and running ConvRot INT8 ControlNet models (including standard ControlNet and Qwen Fun ControlNet). It guarantees clean in-place dequantization prior to model construction, establishes native `bfloat16` and `float16` kernel precision, and synchronizes ControlNet tensor dtypes with diffusion UNet backbones.

---

## 2. Technical Background & Root Cause Analysis

### 2.1 The Parameter Gradient Failure Mechanism
When loading a ControlNet checkpoint, the Forge loader determines the model type and invokes the model class constructor. For Qwen Image Fun ControlNet (`modules_forge/supported_controlnet_qwen_fun.py`), `_build_comfyui_fun_model` initializes the underlying network:
```python
model = comfy_qwen_cn.QwenImageFunControlNetModel(
    control_in_features=in_features,
    inner_dim=inner_dim,
    ...
    dtype=dtype,
)
```
Inside `QwenImageFunControlNetModel.__init__`:
```python
self.control_img_in = operations.Linear(control_in_features, inner_dim, device=device, dtype=dtype)
```
Which delegates to PyTorch's native `nn.Linear`:
```python
self.weight = Parameter(torch.empty((out_features, in_features), **factory_kwargs))
```
When `factory_kwargs` or state dict assignment received raw quantized `torch.int8` tensors, PyTorch's C++ constructor rejected the allocation:
```text
File "...torch/nn/parameter.py", line 57, in __new__
    return torch.Tensor._make_subclass(cls, data, requires_grad)
RuntimeError: Only Tensors of floating point and complex dtype can require gradients
```
Because `requires_grad=True` is the default for `nn.Parameter`, PyTorch enforces that parameters must have floating-point dtypes (`float32`, `float16`, `bfloat16`, etc.). Attempting to instantiate layers or inspect weights while they reside in INT8 representation immediately triggered this fatal exception.

### 2.2 The Fallback Dequantization Dtype Gap
When ControlNet checkpoints are quantized using ConvRot INT8 (HSWQ), each weight tensor is stored as an 8-bit integer tensor accompanied by `.weight_scale` and `.comfy_quant` metadata.
In previous versions:
- `dequantize_state_dict_inplace` only passed code `1` (fp16) or code `0` (fp32) to the C++/CUDA kernel.
- Checkpoints trained and saved with `bfloat16` compute activations were forcibly cast to `float16`.
- When the resulting `float16` ControlNet residual activations were injected into modern `bfloat16` diffusion UNet backbones (e.g., Flux1, Qwen Image), PyTorch threw an unhandled tensor type mismatch error during matrix addition.

### 2.3 Partial Device Migration vs. Dtype Alignment
In `QwenFunControlNetPatcher.process`, after building the Fun ControlNet model, Forge prepared the model for the sampling pass:
```python
# Previous implementation:
fun_model.to(diffusion_model.load_device)
```
While this moved the model parameters to the target GPU, it completely omitted dtype alignment. If the ControlNet model was instantiated in `float32` or `float16`, but the diffusion model was running in `bfloat16`, cross-attention and feature projection layers failed on the very first forward step.

## 3. Implementation Details & Code Walkthrough

### 3.1 Pre-Construction In-Place Dequantization (`modules_forge/supported_controlnet.py`)
In `ControlNetPatcher.try_build_from_state_dict`, dequantization is now invoked prior to shape probing or model building:
```python
# modules_forge/supported_controlnet.py
# Dequantize ConvRot INT8 state dict in-place to target compute dtype before model instantiation
dequantize_state_dict_inplace(controlnet_data)
```
This guarantees that all weights are cleanly unrotated and converted to standard floating-point tensors before any `nn.Parameter` instantiation occurs.

### 3.2 Qwen Fun State Dict Pre-Dequantization & Dtype Synchronization (`modules_forge/supported_controlnet_qwen_fun.py`)
```python
# modules_forge/supported_controlnet_qwen_fun.py
def _build_comfyui_fun_model(loaded):
    # Dequantize state dict to bfloat16 in-place prior to shape probing
    dequantize_state_dict_inplace(loaded, compute_dtype=torch.bfloat16)
    ...
    return model

class QwenFunControlNetPatcher:
    def process(self, ...):
        # Synchronize target device AND floating-point compute dtype
        target_device = diffusion_model.load_device
        target_dtype = getattr(diffusion_model, "dtype", torch.bfloat16)
        if target_dtype not in (torch.bfloat16, torch.float16, torch.float32):
            target_dtype = torch.bfloat16
        
        fun_model.to(device=target_device, dtype=target_dtype)
```

### 3.3 Native bfloat16 C++/CUDA Kernel Code & Hadamard Cache (`backend/patch_comfy_quant_layout_fallback.py`)
Extended kernel dispatch to support code `2` for `bfloat16` and integrated per-device Hadamard caching:
```python
# backend/patch_comfy_quant_layout_fallback.py
code = 2 if compute_dtype == torch.bfloat16 else 1

# Hardware-accelerated GPU Hadamard cache
hadamard_matrix = get_hadamard_matrix(group_size, device=weight.device, dtype=compute_dtype)
native_kernel.dequantize_convrot(weight, scale, hadamard_matrix, code)
```

### 3.4 Inference Mode Autograd Isolation
Wrapped model construction and weight copying routines:
```python
with torch.inference_mode(False), torch.no_grad():
    model = _build_comfyui_fun_model(loaded)
```
