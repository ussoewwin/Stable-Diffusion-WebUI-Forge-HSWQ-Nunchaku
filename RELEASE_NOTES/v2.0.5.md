# Version 2.0.5 — Krea2 INT8 OutOfMemory (OOM) Fix & Comprehensive 16GB VRAM Management (Issue #3 Resolution)

This release resolves the critical `CUDA out of memory` crash encountered when loading and running Krea2 (`SingleStreamDiT`, e.g., `moodyKrea2Mix...covrot_int8.safetensors`) under `int8` and `int8 (fp16 LoRA)` (`unet_storage_dtype: 'int8_tensorwise'`). It systematically addresses and resolves [Issue #3](https://github.com/ussoewwin/Stable-Diffusion-WebUI-Forge-Nunchaku/issues/3).

---

| Item | Detail |

## 2. Technical Background & Root Cause Analysis

### 2.1 The Issue #3 Problem Statement
As reported in [Issue #3](https://github.com/ussoewwin/Stable-Diffusion-WebUI-Forge-Nunchaku/issues/3), running quantized Krea2 checkpoints triggered severe memory exhaustion. Krea2 utilizes an expansive `SingleStreamDiT` architecture containing dozens of transformer blocks where image and text tokens share a single combined sequence. When combined with the high-parameter `Qwen3-VL-4B` text encoder, the memory requirements easily overwhelm standard 16GB graphics cards unless quantization and offloading contracts are strictly enforced.

### 2.2 SingleStreamDiT Operations Dispatch Gap
In `modules_forge/hswq_int8.py`, `load_unet_int8_branch` selects and injects quantized operations (`int8_ops`) into the model architecture based on class matching:
```python
if isinstance(model, (Flux, SD3, WanVideo, HunyuanVideo)):
    ...
```
`SingleStreamDiT` (and `CosmosTransformer3DModel`) was not present in this list. Consequently, Krea2 bypassed the `int8_ops` injection entirely and fell back to stock ComfyUI `manual_cast` with `dtype=None`. When the state dict containing INT8 quantized tensors was loaded:
1. All 224 quantized weights failed to match the unquantized parameter shapes and were flagged as `Unexpected keys`.
2. PyTorch initialized the default unquantized layer weights in FP32 (float32, 4 bytes per parameter), expanding the model footprint to approximately **48.9 GB**, which immediately triggered an unrecoverable CUDA OutOfMemoryError.

### 2.3 Premature Text Encoder Dequantization
In `backend/loader.py`, `split_state_dict` historically checked state dicts for quantized weights and executed `dequantize_state_dict_inplace`. For modern multimodality encoders like `Qwen3-VL-4B`:
- Expanding INT8 weights to uncompressed FP16 required allocating an 8.1 GB contiguous memory buffer.
- On Windows systems, host-to-device transfers and memory copies caused text encoder loading to stall for 8 to 31 seconds.
- Furthermore, ComfyUI's native ops already natively support `comfy_quant` INT8 `QuantizedTensor` through `MixedPrecisionOps`, rendering pre-dequantization wholly redundant and counterproductive.

### 2.4 Text Encoder VRAM Retention and Inter-Engine Desynchronization
Forge and ComfyUI maintain distinct internal memory management caches. When `comfy_te_glue` initialized the CLIP model:
1. `model_options` did not strictly specify `offload_device = cpu`, allowing parts of the text encoder to remain pinned in GPU VRAM after encoding the positive/negative conditioning.
2. Even after `clip.patcher` was moved, ComfyUI's `model_management.current_loaded_models` still retained a strong reference to the text encoder, preventing garbage collection.
3. As a result, approximately **4.24 GB of VRAM remained occupied**, leaving only ~11.8 GB free when attempting to load the massive Krea2 UNet.

### 2.5 Module-Level CPU Swapping for `comfy_cast_weights`
When Forge loads a large diffusion model, `backend/memory_management.py` calculates memory budgets and splits model blocks between VRAM and system RAM (`LoadedModel`). However:
- The parameter profiling loop explicitly filtered for known parameter types and standard `comfy.ops.manual_cast`.
- Modules utilizing `comfy_cast_weights` (including `MixedPrecisionOps` and `int8_ops`) were not recognized as swappable module candidates.
- The manager attempted an all-or-nothing allocation, demanding ~12.9 GB of contiguous VRAM when only ~11.8 GB was available, causing an immediate OOM crash before the first step.

### 2.6 PyTorch Inference Mode Version Counter Conflict
During tensor device migrations (`cpu` to `cuda` and vice versa), `comfy.ops._quantized_apply` rewrites inner weight references. In PyTorch 2.4+, executing parameter rewrites inside an active `torch.inference_mode()` context triggers:
```text
RuntimeError: Cannot set version_counter for inference tensor
```
This aborted the unload/swap routine midway, leaving models half-loaded and corrupted in memory.

## 3. Implementation Details & Code Walkthrough

### 3.1 SingleStreamDiT & Cosmos Operations Dispatch (`modules_forge/hswq_int8.py`)
Added `SingleStreamDiT` and `CosmosTransformer3DModel` to the operations injection list in `load_unet_int8_branch`:
```python
# modules_forge/hswq_int8.py
if model_cls_name in (
    "Flux", "SD3", "WanVideo", "HunyuanVideo", "Lumina2Transformer2DModel",
    "ZImageTransformer2DModel", "SingleStreamDiT", "CosmosTransformer3DModel"
):
    model.diffusion_model.set_operations(int8_ops, computation_dtype=computation_dtype)
```
This guarantees that all 224 linear layers are instantiated with `comfy_cast_weights` and `torch.bfloat16` compute dtype, eliminating parameter expansion.

### 3.2 Native INT8 Text Encoder Loading (`backend/loader.py`)
Updated `split_state_dict` to detect and bypass dequantization for Comfy-native multimodality encoders:
```python
# backend/loader.py
if guess_clip_type in ("qwen3vl_4b", "qwen3_4b", "qwen3_06b", "gemma2_2b"):
    # Skip premature full-state-dict dequantization; ComfyUI MixedPrecisionOps handles comfy_quant natively
    pass
else:
    dequantize_state_dict_inplace(clip_sd, compute_dtype=computation_dtype)
```
In addition, `_load_krea2_mixed_precision_unet` explicitly passes `computation_dtype`:
```python
unet = load_unet_int8_branch(
    sd,
    unet_storage_dtype=unet_storage_dtype,
    computation_dtype=computation_dtype,
)
```

### 3.3 Guaranteed CLIP CPU Offloading (`backend/comfy_te_glue.py` & `memory_management.py`)
Enforced CPU offload in model options and guaranteed comprehensive teardown:
```python
# backend/comfy_te_glue.py
te_model_options = {
    "offload_device": torch.device("cpu"),
    "initial_device": torch.device("cpu"),
}

def offload_comfy_clip(clip_patcher):
    if clip_patcher is not None:
        import comfy.model_management as mm
        mm.unload_model_clones(clip_patcher)
        if hasattr(clip_patcher, "model"):
            clip_patcher.model.to(torch.device("cpu"))
        torch.cuda.empty_cache()
```
In `backend/memory_management.py`, `free_memory` cascades to ComfyUI:
```python
# backend/memory_management.py
def free_memory(memory_required, device, keep_loaded=[]):
    ...
    # Cascade eviction to ComfyUI model management
    import comfy.model_management as mm
    mm.free_memory(memory_required, device)
```

### 3.4 Module-Level CPU Swapping for `comfy_cast_weights` (`backend/memory_management.py`)
Extended `build_module_profile` to measure and register `comfy_cast_weights` layers:
```python
# backend/memory_management.py
for name, module in model.named_modules():
    if hasattr(module, "comfy_cast_weights") or hasattr(module, "weight"):
        # Profile module weight memory footprint
        ...
```
When free VRAM is insufficient to hold the entire UNet, `LoadedModel` partitions the module list: the first ~11.0 GB of layers remain resident in GPU VRAM, while the remaining ~1.87 GB are dynamically swapped from CPU memory during the forward pass.

### 3.5 Inference Mode Autograd Isolation (`backend/patch_comfy_quant_layout_fallback.py`)
Wrapped `_quantized_apply` to isolate parameter version counters from PyTorch inference mode:
```python
# backend/patch_comfy_quant_layout_fallback.py
def _safe_quantized_apply(fn, tensor):
    with torch.inference_mode(False), torch.no_grad():
        return _orig_quantized_apply(fn, tensor)
```
